# Nook
RUNTEQ卒業制作アプリ（第二案）

## 1. サービス概要

- このサービスはどんなサービスか
子育て中の人の、子育てに関してちょっと知りたいことや、子どもの成長を気遣わず共有したい時に安心してゆるく繋がれるアプリ

- 誰の、どんな課題を、どう解決するか
「子育て中の人」の「ゆるく繋がりたいけど気は使いすぎたくないという思い」を「安心して子育てについて話したり、相談したり、子どもの成長を喜び合えるコミュニティを作ることで解決する」

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

このアイデアの元になった

- いつ<br>
	- 10〜15分くらいの短い隙間時間をほっこりできるような時間にしたい時
	- 子育てについてゆるく語り合いたい時
	- 子育てについてちょっと聞いてみたいことがある時
	
- どんな状況で<br>
	- 子育て中

- どんな気持ちになったか<br>
	- 他の子育て中の人とゆるく繋がりたい 
	- みんなの「うちはこうしてるよ」を知りたい
	- 安心して子育てについての情報を見たり話をしたい

- 具体的なエピソード<br>
子育て中の友人と話している時に、以下のようなニーズがあることがわかった。
	- 仕事も家事育児もしているとまとまった時間は作れないけど、短い時間でほっこりした気持ちになれるようなコミュニティの場が欲しい。
	- 子どもの成長で嬉しかったことや自慢したくなるようなことは、親族以外には気を遣って話しづらい。気兼ねなくお互いの子どもの成長を一緒に喜び合えるような場があると嬉しい。
	- ちょっとした子育てのコツやライフハック情報をシェアしたい。
	- SNSでは「こうすべき」「子育てのNG」など不安になる投稿も多くあるけど、どうしても目に入ってしまい、初めての子育てだと流されてしまうこともあるから不安を煽るものではなくて安心して見れるものが欲しい。
	- 子どもの発達に関することなど、プロに相談するほどではないけど「みんなどうしてるのかな」といったライトな疑問を聞きたい。
	- 完全匿名性の質問機能がほしい。アカウントから遡って矛盾を指摘されて嫌な気持ちになったことがある。
	- リアクション数が表示されないコミュニティがいい。

### 2-2. なぜそれが「気になった」のか

同じ体験をしても、気にしない人もいるが、なぜ自分はそれが気になったのか？

- 自分の性格
	- あるべき思考が強め
	- 気にしい
	- 細かいことが気になる

## 7. このアプリで実現すること

### MVPで作る機能
- ユーザー登録機能 
- テーマに対してコメントを投稿できる機能
- 質問を投稿できる機能
- リアクション機能<br>
	※リアクション数が少ないと、共感していてもなんだか少しリアクションするのをためらうことがあるという意見があったため、コメント・質問いずれも閲覧者にリアクション数は表示しない。
	- コメント<br>
	- 「❤️（いいね！ボタン）」：投稿に対して「いいね！」を伝えたいと思ったら使う。
	- 「🖐️（うちも！ボタン）」：テーマが「うちのお尻ふき」で「コストコ」とコメントした人がいたら、「うちも同じの使ってる！」という共感を伝えたい時に使う。
	- 「☕️（お疲れ様ボタン）」：テーマが「最近子どもの言動で困ったこと」で「来客者の鞄の中身をあさっていた」とコメントした人がいたら、「それは大変！お疲れ！」とねぎらいたい時に使う。
	- 質問<br>
	- 「📝（知りたい！ボタン）」:自分たちも気になっている質問が投稿されていたら、「うちもそれ知りたい！」と共感を伝えたい時に使う。
	- 「保存」：あとでゆっくり見たい時に使う。


### 本リリースで作る機能
- タグ付け機能<br>
	「# 新生児」「# おむつ」「# 離乳食」「# ハーフバースデー」「# 保育園の洗礼」「# ファーストシューズ」「# おうち遊び」「# ランドセル」「# 時短」「# 子連れ旅行」「＃お弁当」など
- コメント・質問投稿削除機能（投稿者自身による削除）
- リアクション解除機能
- キーワード検索機能
- 画像アップロード機能<br>
	→ 子どもの顔や学校名、住所など個人を特定できる情報が含まれる画像の投稿を防ぐため、画像投稿時に「顔・学校名・住所など個人を特定できる情報が含まれていないか」を確認するダイアログを表示する。

- NGワード登録
- ミュート機能<br>
	→ 見たくないユーザーの投稿を非表示にできる。将来的にユーザーの個別チャット機能などを実装する場合は、ブロック機能も検討する。
- 通報機能<br>
	→ 投稿の右上に「･･･」ボタンを設置し、タップすると「ミュート」「通報」が表示され、「通報」をタップすると、理由を選択して「通報」ボタンをタップして運営に通報できる。通報された投稿については、運営が管理画面から、必要に応じて投稿の削除を行うことができる。
- テーマ募集機能<br>
→ ユーザーからテーマを募集し、運営がピックアップする。カテゴリは例えば
	- みんなどうしてる？
	- ライフハック
	- 成長シェア
	- 聞いて聞いて<br>
	から選んでユーザーは月1回テーマを運営に送信することで、その後も通常通りみんなの投稿を見ることができる運用を想定。（BeRealのようなイメージ）
	テーマをユーザーから募集することで、ユーザーが話したいテーマ＝子育て中の人が話したいテーマになるため、みんなで作るコミュニティにできると考えている。<br>
共通のテーマや話題についてゆるく話したり、リアクション機能で共感し合ったりできることが、本アプリのコンセプトである「安心してゆるく繋がりたい」という気持ちを満たしてくれるものになると考える。


## 8. このアプリの懸念点とその対策

### 懸念点①

- 何が問題になりそうか：他のアプリとの差別化ができるか
- なぜそう思うか：機能がほぼ同じものがある
- そのために考えている対策：
	- 呟きたいことを呟くというよりは、子育てに関する情報や喜びをみんなで共有する場にしたい
	- 他の育児コミュニティでは、「攻撃されるかもしれない」「過去の発言との矛盾を指摘されるかもしれない」という不安から投稿をためらうことがある。本アプリでは、完全匿名質問やNGワード機能、落ち着いた色味やリアクション数を表示しない設計など、安心して参加できる空気感を作ることを目指す。

### 懸念点②

- 何が問題になりそうか：投稿した画像が悪用される可能性がある
- なぜそう思うか：写真を使用した犯罪が増えているため
- そのために考えている対策：
	- 画像投稿時に「お子さまやご家族の顔、学校名、住所など、個人を特定できる情報が含まれていないか」を確認する確認ダイアログと「確認しました」というチェックボックスを表示することを検討している。
	- 投稿後に「やっぱり削除したい」と思った場合に対応できるよう、投稿したコメントと質問を投稿者自身が削除できる機能の追加を考えている。
	- 個人開発・個人運営を想定しているため、通報機能については運営側で継続的な対応が必要になることも踏まえて、ユーザーから報告があれば必要に応じて管理画面から削除するなどで対応するが、まずはユーザー自身が安心して利用できる仕組みを優先して実装する。


## 9. 今後の展開・発展の方向性

このアプリは、**「投稿して終わり」にならないために**どんな広がりが考えられるか？

### 観点

- ユーザーはなぜ使い続ける？
	- 「みんなどうしてる？」と思った時に気軽に質問できるから
	- 子どもの成長を誰かに聞いてほしい時に共有できるから
	- 仕事・家事・育児の合間に、安心して他の子育て中の人と交流できるから

- 続けることで何が変わる？
	- 世間とつながっている感覚になり、一人で子育てしているんじゃないんだと思える。
	- 子育てについて安心して話せるようになる。

- データが溜まると何ができる？
	- よりユーザーのニーズに沿った情報を得ることができる

- 他の人と関わる余地はある？
	- 他の子育て中の人とのコミュニケーションがメイン機能

### 今考えている発展案

- 機能追加の方向性：<br>
	- グループチャット機能<br>
	テーマはなんでもOK（運営が作るか、ユーザーが作るかは未定）例えば、保育園の入園をもうすぐ控えている人たちが集まったグループチャットなら、保育園から指定された準備物の細かい疑問（汚物入れの袋のサイズってどれくらい？など）について話しあったり、言われてみればそれってどうなんだろう？を自由に会話して解消できたりする

	- 個別チャット機能<br>
	アプリを使い続けていくと「この人と話が合いそうだからもっと話してみたい」と思う人が現れることもありそうという意見があったため、不特定多数とつながるだけでなく、特定の人とより深くコミュニケーションを取れる機能があれば孤独感の解消に繋がると考える。ただ、個人間のやりとりに運営は責任は持てないため機能を追加する時には運用方法を細かく決めておく必要があると思う。

	- 画像認識による自動検知機能<br>
	個人が特定される情報が画像に含まれていないか検知するために有効と考えた。個別にダイアログで注意喚起もするが、自動検知機能を追加することで、よりユーザーの安心感につながると考える。


- UI・体験の改善：
	- ライトモードとダークモードの切り替え

- 機能以外の工夫：
	- コミュニティの育て方：ヒアリングをした友人をはじめとして普及させていく予定。
	- 運営としての関わり方：個人開発という面から、積極的に介入するのではなく見守るという位置付けをとる。

- なぜこの技術を使うのか
	- Ruby on Railsは、投稿・コメント・認証などコミュニティサイトで必要となる機能を効率よく実装できるため選択した。
	- データベースにはRailsとの親和性が高く、本番環境でも広く利用されているPostgreSQLを使用する。
	- デプロイ先にはRenderを利用し、Webアプリケーションを公開できる環境を構築する。
	- 画像投稿機能には、RUNTEQのカリキュラムで実装経験のあるCarrierWaveを利用する予定。
	- 検索機能にはRansackを利用し、投稿を探しやすいアプリを目指す。

- 今回チャレンジしたい点
	- コメントを中心としたコミュニティ機能の実装
	- 使いやすいUI・UXの設計
	- 画像投稿機能の実装
	- 投稿検索機能の実装
	- リアクション機能の実装

- 不安な点
	- 投稿・コメント・リアクションなど複数のモデルが関連するため、データベース設計が複雑になる可能性があること
	- コミュニティサービスでは投稿内容の管理やバリデーションも考慮する必要があること
	- 本リリースで予定している検索機能や画像投稿機能を、開発期間内に完成させられるか
